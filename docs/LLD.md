LLD — Low Level Design

At the low level, the request flow starts from the client and reaches a Next.js API route handler. The request is first authenticated using JWT and the user's identity and role are extracted from the token. The request body or parameters are then validated using Zod. After validation, the controller handles the request and calls the relevant service. The service contains the actual business logic and uses Prisma to perform database operations in MySQL. For authentication, the signup service validates the user data, hashes the password using bcrypt, and creates the user. During login, the system finds the user, compares the provided password with the stored bcrypt hash, and generates a JWT containing the user ID and role. For warranty lookup, the user provides a serial number, the service searches for the corresponding Product, and then retrieves the associated warranty documents and repair history. Repair history supports CRUD operations where authorized admins can create, read, update, and delete repair records, while users can view their repair information. Pagination is implemented for repair history using page and limit values, where the database query calculates the required skip value and retrieves only the requested number of records. Warranty document management allows an admin to upload a PDF, associate it with a Product, and store the document information in the WarrantyDocument table. The database contains relationships between User, Product, WarrantyDocument, and RepairHistory, with the Product serial number maintained as a unique field. The overall request flow is Client → Next.js Route Handler → Authentication/Validation → Controller → Service → Prisma → MySQL, while the response follows the reverse path back to the client.
